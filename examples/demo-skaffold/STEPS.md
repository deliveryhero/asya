# Skaffold Demo: Step-by-Step

Two teams, two flows, one mesh. Demonstrates the full developer workflow:
compile, build, expose, deploy, test, observe.

## Prerequisites

- GKE cluster with Asya platform installed (asya-crossplane, asya-crew, asya-gateway)
- `skaffold`, `kubectl`, `uv` installed
- GCP auth configured (`gcloud auth login`)
- Artifact Registry repository for images

```bash
# Set your registry (Artifact Registry, GCR, etc.)
export REGISTRY=europe-west1-docker.pkg.dev/YOUR_PROJECT/YOUR_REPO

# # Install asya CLI
# uv pip install git+https://github.com/deliveryhero/asya.git#subdirectory=src/asya-lab
```

All commands run from `examples/demo-skaffold/`.

```bash
cd examples/demo-skaffold
```

## Flow 1: text-flow (Team A -- proper Python package)

**Source:** `src/team-a/proper-package/nlp/text_flow.py`
**Pipeline:** start-text-flow -> analyze (x2) -> summarize -> x-sink
**Image:** `src-team-a-proper-package` (defined in `src/team-a/proper-package/skaffold.yaml`)

### 1. Compile

```bash
uv run --project ../../src/asya-lab asya compile text-flow -f src/team-a/proper-package/nlp/text_flow.py
```

Output:
```
[+] Compiled flow 'text-flow'
    actors:    3 calls -> 2 manifests [actor-analyze, actor-summarize]
    routers:   1 [start-text-flow]
    manifests: compiled/text-flow/manifests/ (5 files)
```

### 2. Build and push image

```bash
cd src/team-a/proper-package
skaffold build --default-repo=${REGISTRY} --file-output=/tmp/text-flow-build.json
cd ../../..
```

### 3. Set image tag in kustomize overlay

Extract the tag from the build output and set it in `common/kustomization.yaml`:

```bash
# Read the built tag
TAG=$(python3 -c "import json; d=json.load(open('/tmp/text-flow-build.json')); print(d['builds'][0]['tag'].split(':')[1].split('@')[0])")
IMAGE=$(python3 -c "import json; d=json.load(open('/tmp/text-flow-build.json')); print(d['builds'][0]['tag'].split(':')[0])")

echo "Image: ${IMAGE}:${TAG}"
```

Edit `compiled/text-flow/manifests/common/kustomization.yaml`:

```yaml
images:
- name: src-team-a-proper-package
  newName: <IMAGE from above>
  newTag: "<TAG from above>"
```

The `kustomizeconfig.yaml` (auto-generated by the compiler) tells kustomize
that `AsyncActor.spec.image` is an image field.

### 4. Expose via gateway

```bash
uv run --project ../../src/asya-lab asya expose text-flow -d "Analyze text sentiment and summarize" --mcp --a2a --context dev
```

This creates the gateway-flows ConfigMap in `common/flow-expose.yaml` and
enables it for the `dev` context (copies to `overlays/dev/`).

### 5. Deploy

```bash
uv run --project ../../src/asya-lab asya k apply text-flow --context dev
```

This does three things:
1. Builds kustomize from `overlays/dev/` (includes namespace, images, flow-expose CM)
2. Applies actors + ConfigMaps via `kubectl apply --server-side`
3. Auto-registers the per-flow CM with the gateway (patches projected volume)

### 6. Verify

```bash
# Check actors
uv run --project ../../src/asya-lab asya k status text-flow

# Check pods
kubectl get pods -n asya-demo -l asya.sh/flow=text-flow
```

### 7. Test via A2A

```bash
# Port-forward the gateway
kubectl port-forward -n asya-demo svc/asya-gateway-api 8080:80 &

# Send a message
curl -s -X POST http://localhost:8080/a2a/ \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "id": "test-1",
    "method": "message/send",
    "params": {
      "message": {
        "messageId": "msg-001",
        "role": "user",
        "parts": [{"kind": "text", "text": "The quick brown fox jumps over the lazy dog. Analyze and summarize."}]
      }
    }
  }' | python3 -m json.tool
```

Expected: `"state": "completed"`

### 8. View logs

```bash
# Tail last 5 lines per actor
uv run --project ../../src/asya-lab asya k logs text-flow --tail 5

# Follow mode (live streaming)
uv run --project ../../src/asya-lab asya k logs text-flow -f

# Both runtime and sidecar containers
uv run --project ../../src/asya-lab asya k logs text-flow -f -c asya-runtime -c asya-sidecar
```

### 9. Clean up

```bash
uv run --project ../../src/asya-lab asya k delete text-flow
uv run --project ../../src/asya-lab asya unexpose text-flow --context dev
```

## Flow 2: greet-flow (Team B -- bare scripts)

**Source:** `src/team-b/bare-scripts/greet_flow.py`
**Pipeline:** start-greet-flow -> greet -> shout -> x-sink
**Image:** `src-team-b-bare-scripts` (defined in `src/team-b/bare-scripts/skaffold.yaml`)

This flow demonstrates:
- Bare Python scripts (no package, no `__init__.py`)
- `# asya: flow` directive on function definition (no decorator import)
- `# asya: actor` directive on function calls
- Adapter call pattern: `payload["greeting"] = greet(payload)` (compiler generates wrapper)
- Skaffold context dirs auto-added to `sys.path` for compile-time imports

### 1. Compile

```bash
uv run --project ../../src/asya-lab asya compile greet-flow -f src/team-b/bare-scripts/greet_flow.py
```

The compiler automatically:
- Detects `# asya: flow` on the function definition
- Detects `# asya: actor` on the `greet()` and `shout()` calls
- Generates an adapter for `payload["greeting"] = greet(payload)` (non-standard pattern)
- Finds `skaffold.yaml` in `src/team-b/bare-scripts/` to resolve the image name
- Adds `src/team-b/bare-scripts/` to `sys.path` so bare imports work

Output:
```
[+] Compiled flow 'greet-flow'
    actors:    1 calls -> 2 manifests [actor-greet, actor-shout]
    routers:   1 [start-greet-flow]
    manifests: compiled/greet-flow/manifests/ (6 files)
                 - asya-actor-greet.yaml
                 - asya-actor-shout.yaml
                 - asya-start-greet-flow.yaml
                 - configmap-greet-adapter.yaml
                 - configmap-routers.yaml
                 - kustomization.yaml
```

Note the extra `configmap-greet-adapter.yaml` -- the compiler generated an adapter
wrapper for the `payload["greeting"] = greet(payload)` call pattern.

If you need to add import paths manually (e.g. for cross-team imports):

```bash
uv run --project ../../src/asya-lab asya compile greet-flow -f src/team-b/bare-scripts/greet_flow.py -I src/team-b/bare-scripts
```

### 2. Build and push image

```bash
cd src/team-b/bare-scripts
skaffold build --default-repo=${REGISTRY} --file-output=/tmp/greet-flow-build.json
cd ../../..
```

### 3. Set image tag

Edit `compiled/greet-flow/manifests/common/kustomization.yaml`:

```yaml
configurations:
- kustomizeconfig.yaml
images:
- name: src-team-b-bare-scripts
  newName: <REGISTRY>/src-team-b-bare-scripts
  newTag: "<tag from build output>"
```

### 4. Expose and deploy

```bash
uv run --project ../../src/asya-lab asya expose greet-flow -d "Greet and shout" --mcp --a2a --context dev
uv run --project ../../src/asya-lab asya k apply greet-flow --context dev
```

### 5. Test

```bash
curl -s -X POST http://localhost:8080/a2a/ \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "id": "test-greet",
    "method": "message/send",
    "params": {
      "message": {
        "messageId": "msg-greet-001",
        "role": "user",
        "parts": [{"kind": "text", "text": "Hello from the greet flow"}]
      },
      "metadata": {"skill": "greet-flow"}
    }
  }' | python3 -m json.tool
```

Note: `metadata.skill` is needed when multiple flows are registered -- it tells
the gateway which flow to route to.

### 6. View logs

```bash
uv run --project ../../src/asya-lab asya k logs greet-flow -f
```

## Key Concepts

### Kustomize manifest structure

```
compiled/<flow>/manifests/
  base/                    # Compiler-generated, regenerated on every compile
  common/                  # User customizations, preserved across recompiles
    kustomizeconfig.yaml   # Teaches kustomize about AsyncActor.spec.image
    flow-expose.yaml       # Gateway flow config (created by uv run --project ../../src/asya-lab asya expose)
  overlays/
    dev/                   # Per-environment overrides
      flow-expose.yaml     # Enabled for dev (copied by uv run --project ../../src/asya-lab asya expose --context dev)
```

### Image resolution

The compiler uses `skaffold.yaml` as the single source of truth for image names.
For each actor call, it:
1. Imports the handler function at compile time
2. Uses `inspect.getfile()` to find the source file
3. Walks up directories to find the nearest `skaffold.yaml`
4. Matches the source file against artifact context directories
5. Returns the artifact image name (e.g. `src-team-a-proper-package`)

Kustomize's `images:` transformer (via `kustomizeconfig.yaml`) replaces bare
image names with full registry paths at deploy time.

### Gateway flow registration

`uv run --project ../../src/asya-lab asya k apply` automatically patches the gateway deployment to mount per-flow
ConfigMaps via projected volumes. No Helm upgrade needed. The gateway reads all
`*.yaml` files in `/etc/asya/flows/` and hot-reloads every 10 seconds.

### Actor naming

| Flow source | Manifest name | Handler |
|------------|---------------|---------|
| `payload = analyze(payload)` | `actor-analyze` | `nlp.analyzer.analyze` |
| `payload = greet(payload)` | `actor-greet` | `greeter.greet` |
| Router (generated) | `start-text-flow` | `routers.start_text_flow` |
