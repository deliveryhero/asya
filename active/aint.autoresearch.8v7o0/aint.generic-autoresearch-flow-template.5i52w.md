## Context

The generic autoresearch flow is the core deliverable: a compiled flow that
orchestrates the experiment loop. Deployed once per namespace, parameterized
by experiment aints.

## Design

### Flow DSL

```python
@flow
def autoresearch(p):
    """Generic experiment loop. Reads experiment spec from payload."""
    while True:
        decision = orchestrator_brain(p)
        if decision["action"] == "stop":
            break
        results = [
            eval_model(train_model(exp))
            for exp in decision["experiments"]
        ]
        p = results_collector(results)
    return p
```

### Actors

**orchestrator-brain**: Mounts git-aint proxy (read/write), memory proxy
(read/write), S3 proxy (read metrics). Calls LLM (direct SDK). Reads
experiment aint for action space, reward spec, budget. Proposes N experiments.
May write new code to git state proxy and trigger x-deploy.

**train-model**: Mounts S3 proxy (data, checkpoints, metrics). Receives
hyperparams in payload. Trains, writes checkpoint + TFEvents. Returns metrics
summary.

**eval-model**: Mounts S3 proxy (checkpoints, test data). Reads checkpoint,
evaluates against fixed test set. Returns metrics. Immutable handler —
enforced by read-only git state proxy + route allowlist.

**results-collector**: Pure function. Aggregates N evaluation results into
ranked summary. No mounts needed (data arrives in payload).

### Experiment Spec (aint)

The orchestrator-brain reads the experiment aint from `/aint/active/...` and
extracts:
- `action_space`: what parameters/architectures to vary
- `environment`: eval handler path + dataset + metric name
- `reward`: metric threshold for success
- `budget`: max iterations, max parallel, max wall time
- `training_handler`: path to training code

### Route Allowlists (auto-generated by compiler)

- orchestrator-brain: [train-model]
- train-model: [eval-model]
- eval-model: [results-collector]
- results-collector: [orchestrator-brain]

orchestrator-brain cannot route to x-sink directly.

### Level 1 vs Level 2

**Level 1 (v0)**: orchestrator-brain calls LLM directly, proposes concrete
parameter combinations.

**Level 2 (future)**: orchestrator-brain asks LLM to generate a search strategy
as Python code (LLAMBO-inspired). Strategy is deployed via x-deploy, generates
experiments, results feed back.
