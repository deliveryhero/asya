Asya

The Message Knows the Way.

A Kubernetes-native actor mesh for async AI/ML pipelines. Each actor is a pure Python function. Each message carries its own route. No central orchestrator. No SDK lock-in. Scale to zero.

Two files. Two owners.

Your Python handler + your AsyncActor YAML spec. That's the entire interface. No SDK imports, no decorators, no framework coupling. Test locally with assert process(payload) == expected.

Deploy as a Kubernetes CRD. Asya injects the sidecar, creates the queue, configures KEDA autoscaling. Your code stays clean.

# handler.py — your code, zero dependencies def process(payload: dict) -> dict: result = model.predict(payload["input"]) return {**payload, "result": result}
# actor.yaml — the platform's job apiVersion: asya.sh/v1alpha1 kind: AsyncActor metadata: name: my-model spec: image: my-model:latest handler: handler.process scaling: minReplicas: 0 maxReplicas: 50

Why Asya

AI workloads are batch jobs — bursty, GPU-heavy, multi-step. Forcing them into synchronous REST adds latency, waste, and cascading failures.

🔀 Decentralized Routing

Envelopes carry prev/curr/next queues. No coordinator can fail. Actors rewrite routing at runtime for agentic patterns, LLM judges, and branching flows.

📉 Scale to Zero

KEDA autoscales each actor independently from 0 to N based on its own queue depth. GPU pods cost nothing when idle. Bursty traffic scales up in seconds.

🐍 Pure Python Handlers

No SDK imports, no decorators, no framework coupling. A handler is dict → dict. Test with pytest, deploy on Kubernetes. That's it.

🔄 Dynamic Pipelines

Routes are data embedded in each message, not code. Write flows as plain Python with if/else and while. The compiler generates router actors automatically.

🔌 Multi-Transport

Pluggable message transports: SQS, RabbitMQ, GCP Pub/Sub. Switch transports without changing handler code. Same actor, different infrastructure.

🤝 A2A + MCP Gateway

Optional HTTP gateway exposes actor pipelines as A2A agents and MCP tools. Sync-to-async bridge with SSE streaming, pause/resume, and task tracking.

Architecture

Actors communicate through message queues. Each message is an envelope that carries its own routing instructions.

Actor Mesh: each actor scales independently, messages carry their own route

Inside Each Actor Pod

Every actor pod has two containers: your Python runtime and the Asya sidecar. The sidecar polls the queue, delivers the envelope to your handler via Unix socket, and routes the response to the next queue in the chain.

Queue → Sidecar → Runtime → Sidecar → Next Queue

Quick Start

Get a local actor mesh running in minutes. Requires Docker, kubectl, Helm, and Kind.

1

Create cluster

kind create cluster --name asya helm repo add crossplane-stable \ https://charts.crossplane.io/stable helm repo update crossplane-stable helm repo add asya https://asya.sh/charts helm repo update asya
2

Install Asya

helm install crossplane \ crossplane-stable/crossplane \ -n crossplane-system \ --create-namespace --wait # Phase 1: infrastructure helm install asya asya/asya-playground \ -n asya-demo --create-namespace \ --set global.transport=sqs \ --timeout 600s --wait # Phase 2: wait for providers, enable actors kubectl wait --for=condition=Healthy \ providers/provider-aws-sqs \ providers/provider-kubernetes \ --timeout=300s kubectl wait --for=condition=Established \ xrd/xasyncactors.asya.sh --timeout=120s helm upgrade asya asya/asya-playground \ -n asya-demo --reuse-values \ --set asya-crossplane.providerConfigs.install=true \ --set enableAsyaCrew=true \ --set helloActor.enabled=true \ --timeout 300s --wait
3

Send a message

aws sqs send-message \ --endpoint-url \ http://localstack-sqs.asya-demo:4566 \ --queue-url \ http://localstack-sqs.asya-demo:4566\ /000000000000/asya-asya-demo-hello \ --message-body '{"id":"test-1", \ "route":{"prev":[],"curr":"hello",\ "next":[]}, "payload":{"name":"Asya"}}' # KEDA scales hello from 0 to 1 # Actor processes, routes to x-sink # Scales back to zero
