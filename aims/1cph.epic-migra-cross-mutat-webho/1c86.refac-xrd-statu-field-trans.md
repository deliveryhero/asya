## Context

The current `xrd-asyncactor.yaml` has SQS-specific fields hard-coded in the status schema:

```yaml
status:
  queueUrl:
    type: string
    description: URL of the SQS queue
  queueArn:
    type: string
    description: ARN of the SQS queue
```

Additionally, spec fields are AWS-leaning:
- `spec.region` defaults to `us-east-1`
- `spec.providerConfigRef` assumes AWS ProviderConfig

## Problem

When adding non-AWS transports (RabbitMQ, Kafka, GCP Pub/Sub), these fields are semantically incorrect:

| Transport | Has ARN? | Address Format | Identifier Format |
|-----------|----------|----------------|-------------------|
| SQS | Yes | `https://sqs.{region}.amazonaws.com/...` | `arn:aws:sqs:...` |
| RabbitMQ | No | `amqp://{host}:{port}/{vhost}` | `{vhost}/{queue}` |
| Kafka | No | `kafka://{bootstrap}` | `{topic}` |
| GCP Pub/Sub | No | N/A | `projects/{project}/subscriptions/{sub}` |

## Proposed Solution

Add transport-agnostic status fields alongside existing SQS ones:

```yaml
status:
  phase: ...
  
  # Transport-agnostic (all transports populate these)
  queueAddress:
    type: string
    description: Connection address for the queue (transport-agnostic)
  queueIdentifier:
    type: string
    description: Unique identifier for the queue resource
  
  # Transport-specific (deprecated, kept for backward compatibility)
  queueUrl: ...     # SQS-specific, mirrors queueAddress
  queueArn: ...     # SQS-specific, mirrors queueIdentifier
```

## Migration Path

1. Add generic fields to XRD schema (non-breaking)
2. Update SQS Composition to populate both generic and SQS-specific fields
3. New transport Compositions only populate generic fields
4. Update sidecar/KEDA configs to use generic fields
5. Deprecate SQS-specific fields in v1beta1

## Files to Modify

- `deploy/helm-charts/asya-crossplane/templates/xrd-asyncactor.yaml`
- `deploy/helm-charts/asya-crossplane/templates/composition-sqs.yaml`
- Future: `composition-rabbitmq.yaml`, `composition-kafka.yaml`
