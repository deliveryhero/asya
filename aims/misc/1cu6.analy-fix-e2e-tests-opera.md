## Failing Tests

### 1. Integration Tests: Operator (FAILURE - Critical)
**Error**: Missing Go module dependency
```
Error: no required module provides package k8s.io/api/resource/v1alpha2; to add it:
  go get k8s.io/api/resource/v1alpha2
FAIL github.com/asya/operator/testing/integration [setup failed]
```
**Root Cause**: k8s.io/client-go@v0.29.2 requires k8s.io/api/resource/v1alpha2, but this package is not resolved in testing/integration/operator's go.mod after the upgrade to v0.32.2 Kubernetes API versions.

**Issue Type**: Operator-specific Go module resolution failure - NOT a timeout issue.

### 2. E2E Tests: sqs-s3 (FAILURE - Multiple Test Suites)
**Failing Test Suites**:
- non-chaos (payload)
- non-chaos (envelope)
- chaos (payload)

**Error Pattern**: Tests fail during E2E deployment phase before test execution can complete.
- Operator test pods fail to start (asya-operator-test pod not found)
- Gateway test pods fail to start (asya-gateway-test-connection pod not found)
- Test-actors test pods fail to start (test-actors-test-dependencies pod not found)
- Helm test failures due to missing test pods

**Visible Test Output**: Tests that ran showed PASSED status (test_gateway_routing_e2e, test_timeout_handling, test_s3_persistence all PASSED), but at least 3 operator-specific tests showed FAILED:
- test_asyncactor_update_propagates (FAILED)
- test_asyncactor_invalid_transport (FAILED)  
- test_operator_e2e (errors during deployment)

**Root Cause**: Since operator integration test failed with Go module error, operator pod cannot start in E2E cluster, causing downstream test failures.

## Error Patterns

### Pattern 1: Go Module Dependency Issue (asya-a92 specific)
```
k8s.io/client-go@v0.29.2/kubernetes/scheme/register.go:66:2: 
  no required module provides package k8s.io/api/resource/v1alpha2
```
- Likely cause: Version skew between k8s.io/client-go v0.29.2 (old version) and k8s.io/api v0.32.2 (new version)
- Solution: Need to update k8s.io/client-go to match k8s.io/api version (0.32.2)
- Currently testing/integration/operator/go.mod has: k8s.io/client-go v1.5.2 (replace directive, wrong version scheme)

### Pattern 2: Test Pod Deployment Failure (E2E downstream effect)
- Helm test-connection pods failing to create
- Operator deployment missing after Kind cluster setup
- Cascading failures due to operator not being available

## Operator Integration Issues

### Issue 1: Kubernetes API Version Mismatch
The PR upgrades k8s.io/api to 0.32.2 but testing/integration/operator/go.mod still has references to v0.29.2 patterns. The k8s.io/api/resource/v1alpha2 package may be:
- Removed in newer k8s.io/api versions
- Moved to a different package path
- Requires explicit dependency declaration

### Issue 2: Operator Pod Deployment Failure
- Operator pod (asya-operator) not found in asya-system namespace
- Likely cause: CRD or RBAC issues introduced by K8s API version changes
- Or: Operator image/deployment itself incompatible with new dependencies

## Relationship to KEDA 2.17.3
- KEDA 2.17.3 may have different CRD requirements (KEDA ScaledObject v1alpha1 vs other versions)
- K8s version compatibility matrix may be stricter in newer versions
- ScaledObject controller behavior changes (per asya-z8g findings)

## Root Cause Summary
**asya-a92 has a DIFFERENT root cause than asya-z8g**:
- asya-a92: Go module dependency resolution failure (k8s.io/api/resource/v1alpha2 missing)
- asya-z8g: Runtime operator behavior change (ScaledObject queue recreation timeout)

Both are related to KEDA 2.17.3 but manifest differently.
