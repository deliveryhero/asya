CLI commands for flow lifecycle management using labels + ConfigMaps (no AsyncFlow CRD).

## Commands

### asya flow deploy
Takes compiled flow output and generates/applies K8s manifests:
1. AsyncActor manifests for routers (new, with labels asya.sh/flow, asya.sh/flow-role=router)
2. Updates existing processor actor manifests to add asya.sh/flow label + asya.sh/flow-role=processor
3. Marks entrypoint/exitpoint actors with asya.sh/flow-role=entrypoint|exitpoint
4. Creates ConfigMap with router code (asya.sh/flow label)
5. Supports --output-dir for GitOps (generate files) or direct kubectl apply for experimentation

### asya flow undeploy
Removes flow resources: kubectl delete asya,configmap -l asya.sh/flow=<name>
Option: --keep-processors to only delete routers

### asya expose
Registers flow as MCP tool in gateway singleton ConfigMap:
- Auto-detects tool name (flow name), description (flow.py docstring), parameters (function signature)
- Updates gateway-tools ConfigMap (mounted by gateway, fsnotify reloads)

## Label Convention
- asya.sh/flow=<name> — flow membership (1:M)
- asya.sh/flow-role=entrypoint|exitpoint|router|processor — role within flow
- Annotations: asya.sh/flow-tool, asya.sh/flow-description for gateway metadata

## 1:M Constraint
One actor can belong to at most one flow. CLI validates before setting label. Reuse = clone actor with new name.

Depends on spec.actor field (asya-v2hs).
