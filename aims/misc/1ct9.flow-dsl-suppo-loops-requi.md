Extend Flow DSL compiler to support for loops.

## Why This Is Separate from While Loops
For loops require a loop variable (iterator) which is a free local variable crossing actor boundaries:

```python
async def multi_tool_agent(state: dict) -> AsyncGenerator[dict, None]:
    for tc in state["tool_calls"]:   # 'tc' is a free local variable
        state = await execute_tool(state)  # await boundary — 'tc' is lost!
        state["messages"].append({"tool_call_id": tc["id"], ...})  # needs 'tc' after await
```

After CPS transformation, the for-loop variable 'tc' exists in one router's scope but is needed in the continuation router's scope (different actor, different pod).

## Depends On
- Local variable serialization across await boundaries (auto-save to payload, auto-restore)
- While loop support (asya-bp6) for shared loop infrastructure (WhileLoop IR node, loop-back routers)

## Approach Options

### Option A: Unroll at compile time (bounded for)
For `for i in range(N)`, unroll into N sequential actor calls. Only works for statically-known bounds.

### Option B: Compile to while + index variable
Transform `for tc in state["tool_calls"]` into:
```python
state["__for_idx"] = 0
while state["__for_idx"] < len(state["tool_calls"]):
    tc = state["tool_calls"][state["__for_idx"]]
    ...
    state["__for_idx"] += 1
```
This serializes the iterator into the payload. Clean approach but requires auto-variable serialization.

### Option C: Sequential tool dispatch (pragmatic)
Instead of iterating tool_calls, process one tool call per loop iteration and let the dispatch router re-enter for the next one. The LLM returns all tool calls, but we execute them one at a time.

## Test Cases
```python
# Bounded for (static range)
async def pipeline(state: dict) -> dict:
    for _ in range(3):
        state = await retry_step(state)
        if state.get("success"):
            break
    return state

# Dynamic for (runtime iterable)
async def fan_out_sequential(state: dict) -> dict:
    for item in state["items"]:
        state = await process_item(state)
    return state
```
