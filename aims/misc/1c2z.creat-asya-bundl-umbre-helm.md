Create an umbrella Helm chart (asya-bundle or asya-all) that simplifies Asya🎭 installation by bundling all required components in a single chart.

## Motivation

New users need to install multiple components separately (operator, CRDs, crew, gateway, optional PostgreSQL). An umbrella chart would:
- Reduce installation complexity
- Provide a working demo environment out-of-the-box
- Include pre-configured test actor for immediate validation
- Serve as a quickstart for evaluating Asya🎭

## Components to Include

The umbrella chart should install (with configurable enable/disable flags):

1. **Operator + CRDs**
   - Install AsyncActor CRD
   - Deploy asya-operator
   - Configure transport (SQS via LocalStack or RabbitMQ)

2. **Crew Actors** (happy-end, error-end)
   - Configure S3/MinIO storage
   - Gateway integration (when enabled)

3. **Gateway** (optional, default: enabled)
   - Optional PostgreSQL deployment with PVC
   - Or external PostgreSQL connection
   - Tool configuration for test actor

4. **Test Hello-World Actor**
   - Simple handler that demonstrates functionality
   - Pre-configured scaling (minReplicas: 0, maxReplicas: 10)
   - Documented in NOTES.txt

5. **Infrastructure Dependencies** (optional, for local testing)
   - LocalStack (SQS + S3)
   - Or RabbitMQ + MinIO
   - PostgreSQL with persistent volume

### Chart.yaml Dependencies
Use Helm chart dependencies to pull existing charts:
```yaml
dependencies:
  - name: asya-operator
    version: ">=0.3.0"
    repository: "file://../asya-operator"
    condition: operator.enabled
  - name: asya-crew
    version: ">=0.3.0"
    repository: "file://../asya-crew"
    condition: crew.enabled
  - name: asya-gateway
    version: ">=0.3.0"
    repository: "file://../asya-gateway"
    condition: gateway.enabled
  # Optional: local testing infrastructure
  - name: postgresql
    version: "15.x.x"
    repository: "https://charts.bitnami.com/bitnami"
    condition: postgresql.enabled
```

### values.yaml Structure
```yaml
# Global settings
global:
  transport: sqs  # sqs | rabbitmq
  storage: s3     # s3 | minio

# Component toggles
operator:
  enabled: true
crew:
  enabled: true
gateway:
  enabled: true
postgresql:
  enabled: true  # Deploy PostgreSQL or use external

# Infrastructure (for local testing)
localstack:
  enabled: true  # Deploy LocalStack for local SQS+S3
rabbitmq:
  enabled: false
minio:
  enabled: false

# Test hello-world actor
helloActor:
  enabled: true
  image: ghcr.io/deliveryhero/asya-hello-actor:latest
  scaling:
    minReplicas: 0
    maxReplicas: 10
    queueLength: 5
```

## Notes

## Design Decisions

### 1. Chart Naming: asya-bundle vs asya-all
**Decision**: **asya-bundle** (clearer intent, follows Helm convention for umbrella charts)

### 2. CRD Installation Strategy
**Problem**: Helm has limitations with CRD lifecycle management
**Options**:
  a) Include CRDs in operator chart (current approach)
  b) Separate kubectl apply step (documented in NOTES.txt)
  c) Use helm pre-install hook
**Decision**: Keep CRDs in operator chart, document pre-requisite in bundle README

### 3. Infrastructure Dependencies Policy
**CRITICAL**: Follow Bitnami Policy from AGENTS.md - NEVER use Bitnami charts
**For PostgreSQL**:
  - Use simple Kubernetes manifests (Deployment + Service + PVC)
  - Store in templates/postgresql/ (conditional on postgresql.enabled)
  - Use official postgres:15-alpine image
**For LocalStack/RabbitMQ/MinIO**:
  - Use official images and simple manifests
  - OR use their official Helm repos (localstack/localstack, etc.)

### 4. Hello-World Actor Implementation
**Options**:
  a) Embed handler code in ConfigMap
  b) Use pre-built image (ghcr.io/deliveryhero/asya-examples)
  c) Build during install (not practical)
**Decision**: Use pre-built image, source in examples/hello-world/

### 5. Transport Configuration
**Decision**: Support ALL transports that Asya supports, but NOT simultaneously (Asya doesn't support multi-transport)
**Default**: SQS via LocalStack (aligns with e2e tests, easier for local testing)
**Supported**: sqs, rabbitmq (any transport from operator's supported list)
**values.yaml**:
```yaml
global:
  transport: sqs  # Primary: sqs, rabbitmq, or any supported transport
  profile: local  # local (with LocalStack/local infra), production (real cloud)
```

### 6. Gateway Tool Configuration
Pre-configure hello actor as MCP tool:
```yaml
gateway:
  routes:
    tools:
    - name: hello
      description: "Test greeting actor"
      parameters:
        name:
          type: string
          required: true
          description: "Name to greet"
      route: ["hello"]
```

### 7. Monitoring (Prometheus/Grafana)
**Decision**: Optional installation (default: false) for quickstart demos
**Rationale**: Useful for demonstrations but adds overhead
**Configuration**:
```yaml
monitoring:
  enabled: false  # Set to true for quickstart demos
  prometheus:
    enabled: true
    retention: 7d
  grafana:
    enabled: true
    adminPassword: admin
```

### 8. Version Pinning Strategy
**Decision**: All components MUST have the same version
**Rationale**: Operator, sidecars it injects, and gateway should be version-aligned
**Chart.yaml**:
```yaml
version: 0.3.0
appVersion: 0.3.0
dependencies:
  - name: asya-operator
    version: 0.3.0  # Exact version match
  - name: asya-crew
    version: 0.3.0
  - name: asya-gateway
    version: 0.3.0
```
**Future work**: Add version constraint validation (see related bead)

### 9. Namespace Strategy
**CRITICAL**: Gateway belongs with business logic, not infrastructure
**Decision**:
  - **asya-system**: Operator + monitoring (Prometheus/Grafana)
  - **Target namespace** (e.g., default): Gateway + PostgreSQL + AsyncActors
**Rationale**: Gateway is part of business logic layer, not infrastructure
**Configuration**:
```yaml
# Install operator + monitoring in asya-system
operator:
  namespace: asya-system
monitoring:
  namespace: asya-system

# Install gateway + actors in target namespace
gateway:
  namespace: default  # Or user-specified namespace
helloActor:
  namespace: default  # Same as gateway
```
**Related**: Existing docs/quickstart/README.md incorrectly installs gateway to asya-system (see fix bead)

## Testing Strategy

1. **Lint**: `helm lint deploy/helm-charts/asya-bundle/`
2. **Template**: `helm template asya-bundle deploy/helm-charts/asya-bundle/ --debug`
3. **Install (Kind) - SQS Profile**:
   ```bash
   kind create cluster --name asya-test
   helm install asya deploy/helm-charts/asya-bundle/ -n default --create-namespace \
     --set global.transport=sqs \
     --set monitoring.enabled=true
   ```
4. **Install (Kind) - RabbitMQ Profile**:
   ```bash
   helm install asya deploy/helm-charts/asya-bundle/ -n default --create-namespace \
     --set global.transport=rabbitmq \
     --set monitoring.enabled=true
   ```
5. **Helm Test**: `helm test asya -n default`
6. **Manual Test**: Send message, verify processing, check gateway
7. **Cleanup**: `helm uninstall asya -n default && helm uninstall asya -n asya-system && kind delete cluster --name asya-test`
