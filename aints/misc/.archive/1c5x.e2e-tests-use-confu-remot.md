## Problem

E2E test configuration references remote registry images (ghcr.io/deliveryhero/*:latest) but actually uses locally-built images that are pre-loaded into Kind. This violates the principle of least surprise and can cause confusion.

## Current Behavior

**Build & Load Flow** (testing/e2e/scripts/deploy.sh):
1. src/build-images.sh builds images with remote registry prefix:
   - ghcr.io/deliveryhero/asya-operator:latest
   - ghcr.io/deliveryhero/asya-gateway:latest
   - ghcr.io/deliveryhero/asya-sidecar:latest
   - ghcr.io/deliveryhero/asya-crew:latest
   - ghcr.io/deliveryhero/asya-testing:latest

2. deploy.sh loads these into Kind cluster:
   kind load docker-image ghcr.io/deliveryhero/asya-operator:latest --name asya-e2e-${PROFILE}

3. E2E values.yaml references remote registry:
   operator:
     image:
       repository: ghcr.io/deliveryhero/asya-operator
       tag: latest
       pullPolicy: IfNotPresent

4. pullPolicy: IfNotPresent makes Kubernetes use pre-loaded local images

## Why This Works (But Is Confusing)

- Images are tagged with remote registry name locally
- Kind pre-loads these images before Helm deployment
- pullPolicy: IfNotPresent prevents remote pulls
- If pre-load fails, Kubernetes tries to pull from remote (may fail for unpublished versions)

## Potential Solutions

### Option A: Use Local-Only Tags
- Build images without registry prefix: asya-operator:e2e-local
- Update E2E values to use local tags
- More explicit that these are local builds
- Requires changing build-images.sh to support local-only mode

### Option B: Add Prominent Documentation
- Add comments in testing/e2e/charts/values.yaml explaining pre-load behavior
- Document in testing/e2e/README.md
- Keep existing behavior but make it explicit

### Option C: Never Pull Policy
- Set imagePullPolicy: Never in E2E values
- Forces use of local images, fails fast if not pre-loaded
- More explicit intent, better error messages

### Option D: Separate E2E Image Registry
- Use different registry/namespace for E2E: localhost:5000/asya-*
- Requires local registry setup in Kind
- Clearest separation between local and remote

## Recommendation

Start with **Option C** (imagePullPolicy: Never) as it's:
- Minimal change (only values.yaml)
- Explicit about local-only usage
- Fails fast if images aren't pre-loaded
- Doesn't require build script changes

Then consider **Option A** for clarity in image naming.

## Files Involved

- testing/e2e/charts/values.yaml (operator, gateway, crew image configs)
- testing/e2e/scripts/deploy.sh (kind load logic)
- src/build-images.sh (image tagging)
- deploy/helm-charts/asya-crew/values.yaml (crew actors)
